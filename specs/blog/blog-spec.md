# Tech Spec — Blog (flatfile, agile-punk)

> **Status:** Ready to build · **Confidence:** 91% · **Spec runs:** 2

## 1. Overview

A static, zero-JS blog rendered by Astro into `dist/` and served from Netlify, living
inside the existing cib.is funnel. Posts are CommonMark `.md` files in an Astro **Content
Collection** (no MDX). The blog adds two routes — `/blog` (flat newest-first index) and
`/blog/<title-slug>` (post detail) — plus an `/rss.xml` full-content feed. Every post detail
ends with a personal, first-person CTA into `/angebot` (the Offers page).

The 19 `ralph` posts from `blog-old-agile-punks/` are migrated in by a one-time script that
writes cleaned `.md` files (images stripped, mechanical fixes applied) named
`YYYY-MM-DD-<title-slug>.md` into `src/content/blog/`. The `title` (the post's `# H1`) and `date`
(the filename prefix) are **derived at build time by a custom content loader** — the loader lifts
the H1 into the title and removes it from the rendered body, and parses the date from the filename.
A light **mechanical** editorial pass runs during migration while every judgment call is logged to a
gitignored `editorial-notes.md`. Once the cleaned posts are committed, the old multi-author dir is
**deleted**. The co-authored `2020-07-30-domiralph.md` publishes with a "mit Domi" note; solo posts
carry no byline; posts by domi/max/chereen are discarded.

Conversion-first: no search, no tags, no related-post engine, no cover images, no video. URLs
are clean and each post emits SEO/OG meta so attract-mode SEO can be switched on after Epic 4
(which removes the site-wide `noindex`). The blog inherits the dark band-merch aesthetic, the
`Prose` primitive, the `Layout`/`BaseHead`/`Button` components, and the Lighthouse ≥ 95 / WCAG AA
budget already established on the site.

## 2. Key Architecture Decisions

1. **Astro Content Collection with a custom loader** (Astro 5) over `src/content/blog/*.md`,
   defined in a new `src/content.config.ts`. Posts are typed by a Zod schema (`title`, `date`,
   optional `coauthor`). This is the first collection on the site (architecture.md flagged it as
   "arrives with the blog, Epic 3"). Rationale: native to the locked stack, gives build-time
   validation (R3/AC2), typed `getCollection()` access, and first-class Markdown rendering with no
   new runtime dependency. *(TD1)*

2. **`title`/`date` are computed at build time by the loader (TD2)**, not baked into frontmatter:
   the loader parses `date` from the `YYYY-MM-DD` filename prefix and lifts the first `# H1` into
   `title`, removing that line from the rendered body (no duplicate heading — AC7). Files therefore
   keep their original H1 in the body and need only `coauthor` frontmatter. Trade-off accepted: a
   custom loader (using the loader context's `renderMarkdown`) is more code than the stock `glob`
   loader + baked frontmatter, and re-derives on every build — but it keeps committed posts close to
   their source and the schema free of filename-coupled fields. *(See Risks — loader complexity.)*

3. **Migration is a one-time Node script** (`scripts/migrate-blog.mjs`) that reads the `ralph` files
   from `blog-old-agile-punks/`, strips images, applies mechanical fixes, and **writes committed
   `.md` files** named `YYYY-MM-DD-<title-slug>.md` into `src/content/blog/` (H1 kept in body;
   `coauthor: Domi` frontmatter only on the collab post). Rationale: published posts are ordinary,
   reviewable source files the editorial pass can edit. After the cleaned posts are committed, the
   old dir is **deleted** (TD6). *(TD1, TD6)*

4. **Slug = filename of the collection entry**, generated by slugifying the title to kebab-case.
   German diacritics are transliterated (`ä→ae`, `ö→oe`, `ü→ue`, `ß→ss`) so URLs are clean, stable,
   and SEO-friendly for later attract mode (R2/R18). The migration writes the same slugified title
   into the filename (after the date prefix) and the loader re-derives it from the H1 with the same
   `slugify`, so file and route agree. URLs are permanent once published, so this policy is locked. *(TD3)*

5. **Excerpt is derived at build time** from the first paragraph of the rendered body (R10) — not
   stored — and feeds both the index card and the per-post SEO/OG `description` (R15). *(TD4)*

6. **RSS via the official `@astrojs/rss` integration**, emitting full post **content** (rendered
   HTML) per item (R16/AC9). Rationale: official, validates against the RSS 2.0 spec, minimal code. *(TD5)*

7. **SEO meta reuses the existing `src/lib/seo.ts` `buildMeta()`**, extended to accept an
   `ogType: 'article'` for posts (today it hard-wires `'website'`). The `noindex,nofollow` guard
   stays — the blog goes public with the rest of the site in Epic 4, no separate switch.

### 3.2 Data model & contracts

**Collection + custom loader (`src/content.config.ts`):**

```ts
// Custom loader: glob the dir, then for each file derive title/date/slug at build time (TD2).
function blogLoader() {
  return {
    name: 'blog-loader',
    async load({ store, renderMarkdown, parseData, generateDigest }) {
      // for each src/content/blog/*.md:
      //   date  = parse YYYY-MM-DD from the filename prefix
      //   raw   = file contents; frontmatter may carry only `coauthor`
      //   title = first `# H1` in the body                    (R10)
      //   body  = raw with that H1 line removed                (AC7)
      //   id    = slugify(title)                               (R18/TD3)
      //   data  = await parseData({ id, data: { title, date, coauthor } })
      //   store.set({ id, data, rendered: await renderMarkdown(body), digest })
    },
  };
}

const blog = defineCollection({
  loader: blogLoader(),
  schema: z.object({
    title: z.string(),               // lifted from the post's # H1 (R10)
    date: z.coerce.date(),           // parsed from the YYYY-MM-DD filename prefix (R10)
    coauthor: z.string().optional(), // e.g. "Domi" → renders "mit Domi" (R9)
  }),
});
```

- **Slug:** the entry `id` = `slugify(title)`; the route is `/blog/[...slug]`. The migration also
  names files `YYYY-MM-DD-<slugify(title)>.md` so the date prefix is parseable and the slug portion
  matches the loader's derived `id`.
- **Title/date:** derived at build by the loader (TD2) — not stored in frontmatter.
- **Body:** CommonMark; the `# H1` is stripped by the loader at build (no duplicate heading — AC7);
  no image markup remains (removed at migration — R6/AC6); `coauthor` frontmatter is `"Domi"` only
  on the collab post (R9).
- **Excerpt:** computed (`firstParagraph`), never stored — feeds the index card and SEO description (TD4).
- **No `tags`, `description`, or `cover` fields** at launch (R10/R11/R12).

**Migration transform contract (per file):**
1. Read `blog-old-agile-punks/<YYYY-MM-DD>-<author>.md`.
2. Skip unless filename contains `ralph` (R5).
3. Read the first `# H1` (to compute the output filename slug) — but **leave it in the body**; the
   loader lifts and strips it at build time (TD2). No frontmatter `title`.
4. Strip every `![...](...)` image line entirely, including caption (R6 image policy).
5. Set `coauthor: Domi` frontmatter iff filename is `2020-07-30-domiralph.md`.
6. Apply safe **mechanical** fixes only (dead links, references to discarded authors/posts);
   append every applied fix and every judgment call needing Ralph to `editorial-notes.md` (R13/R14).
7. Write `src/content/blog/<YYYY-MM-DD>-<slugify(title)>.md` (date prefix preserved for the loader;
   slug portion = the route slug). Frontmatter is empty except `coauthor` where applicable.
8. Assert slug uniqueness across all outputs — fail loudly on collision (URL permanence).
9. After the 19 files are written, reviewed, and committed, **delete `blog-old-agile-punks/`** (TD6).

### 3.3 External integrations / config

- **`@astrojs/rss`** — new dev dependency; `astro add` or manual install. Feed at `/rss.xml`,
  `site` already set in `astro.config.mjs` (`https://ralphcibis.netlify.app`).
- **`.gitignore`** — add `editorial-notes.md` (R14/AC8).
- **`netlify.toml`** — no change; the existing `X-Robots-Tag: noindex` header covers `/blog/*` too.
- **`astro:assets`** — already the site image pipeline; available to posts that later add an image
  (R4/AC3), but no migrated post uses one.

pages (testable in e2e). Unit tests live next to source / in `tests/`; e2e in `e2e/blog/*.spec.ts`.

## 6. Testing Strategy

- **Unit / integration (Vitest):** `slugify`, `excerpt`, `seo`, the migration transforms, the
  collection schema, and the `.gitignore` guard — all pure/fast, run per task (testing.md).
- **e2e (Playwright Test, `e2e/blog/`):** index ordering & content, post render, CTA navigation,
  RSS validity — run in full QA against `npm run preview`.
- **Agentic click-through (`verify-epic`):** confirm the index → post → CTA → Offers flow and RSS in
  a real browser; optional `--screenshots`.
- **AC mapping:** each AC is asserted by the task(s) in §4; AC9 (RSS validity) uses an XML parse +
  schema check; AC5 ordering asserts the topmost post is 2023-12-31.
- **Lighthouse gate:** `/blog` and a sample post must hold Performance/A11y/Best-Practices ≥ 95;
  SEO stays 66-by-design until Epic 4 (the `is-crawlable` audit).

## 7. Risks & Non-functional

- **Performance / CLS:** zero-JS, inlined CSS, no images on migrated posts → low risk. Any future
  post image must use `astro:assets` with a fixed aspect-ratio wrapper (coding-guidelines budget).
- **Accessibility:** post body must keep a sane heading order — with the H1 removed and `title`
  rendered as the page `<h1>`, in-body `##`/`###` must not skip levels; the `Prose` link styling
  already meets AA contrast. German `lang="de"` inherited from `Layout`.
- **a11y of the CTA:** the CTA button reuses `Button` (visible focus ring, ink-on-neon ≥ 5.7:1).
- **Custom loader complexity (TD2):** lifting the H1, parsing the filename date, and rendering the
  H1-stripped body in a custom loader is more moving parts than baked frontmatter, and re-runs on
  every build. Mitigation: keep the derivation in exported pure helpers (unit-tested in T1) and let
  `renderMarkdown` from the loader context do the render; the loader is small and fully covered.
- **URL permanence:** slugs are forever once public (R2 attract-mode). The transliteration policy
  (TD3) is the single biggest irreversible choice — collisions between two posts that slugify to the
  same string must fail the build loudly (uniqueness assertions in both T1 and T4).
- **GDPR / legal:** no tracking/cookies/third-party — unchanged; `noindex` until Epic 4.
- **Editorial / reputational:** mechanical fixes only; voice changes are flagged, never applied
  (R13). `editorial-notes.md` must stay gitignored so private notes never ship (AC8).
- **Migration reversibility (TD6):** the old dir is **deleted** after the cleaned posts are committed,
  so re-running the script is impossible once it's gone — the committed `src/content/blog/*.md` files
  (and git history) become the only source. Mitigation: only delete after the 19 posts are reviewed
  and committed; `editorial-notes.md` captures the discarded-author context the deletion removes.
- **Rollback:** the blog is additive (new routes); removing the two pages + RSS endpoint reverts the
  site to its pre-blog state with no data migration.
